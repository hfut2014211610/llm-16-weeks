## 1. 跑 gpt.py：如何对比训练前后的效果

**提问**：开始跑 gpt.py 了，怎么对比训练前后的效果？

看两样东西：**loss 数字**和**生成的文字**。

- 先跑 `python gpt.py cpu 0`：不训练，直接写一段乱码，loss 约 4.3。
- 再跑 3000 步：val loss 应该在 1.8 左右，文字会变成“人名 + 冒号”的剧本格式。

```python
# 每 500 步写一段（替换 gpt.py 训练循环里的 if 块）
    if it % eval_interval == 0:

        print(decode(model.generate(start, 100)[0].tolist()))
```

## 2. softmax 速查

**提问**：softmax 忘了，简单介绍一下。

softmax 把一组任意的分数变成概率：每个数都是正的，加起来等于 1，分数高的分到的概率更大。做法就两步：先对每个分数取指数，再除以总和。

**公式**：softmax(xᵢ) = e^xᵢ ÷ (e^x₁ + e^x₂ + … + e^xₙ)

**例子**：分数 [2.0, 1.0, 0.1]

1. 取指数：e^2.0 = 7.389，e^1.0 = 2.718，e^0.1 = 1.105
2. 求和：7.389 + 2.718 + 1.105 = 11.212
3. 各自除以总和：**[0.659, 0.242, 0.099]**，加起来正好等于 1

**为什么用指数**
- 负数也能变成正数，概率不会是负的
- 会拉开差距：分数只差 1，概率就差大约 2.7 倍
- e^(−∞) = 0，所以把分数设成 −∞ 就能让它的概率变成 0。因果掩码就是靠这一点

**只看差距，不看绝对值**：[2, 1, 0.1] 和 [102, 101, 100.1] 算出来的概率完全一样。

**分数差距太大会“非黑即白”**：[30, 20, 10] → [0.99995, 0.00005, ≈ 0]；缩小十倍变成 [3, 2, 1] → [0.67, 0.24, 0.09]。注意力里“除以 √d”就是为了避免前一种情况。

**在 gpt.py 里用在两处**
- `generate`：65 个分数 → 下一个字的概率
- `Head`：注意力打分 → 加权平均用的权重

```python
import torch, torch.nn.functional as F
print(F.softmax(torch.tensor([2.0, 1.0, 0.1]), dim=-1))
# tensor([0.6590, 0.2424, 0.0986])
```

### 补充：softmax 是不是“归一化到 [0,1]”？

**提问**：softmax 其实就是把正负权重值归一到 [0,1] 区间的归一化函数吧？

理解对了大半，有两点要补：

- 输入是“分数”，输出才是权重或概率。
- 关键不只是落在 0 到 1 之间，而是**加起来等于 1**。sigmoid 也能把数压进 0 到 1，但加起来不等于 1，所以不能当“下一个字”的概率。

## 3. 词向量：从 word2vec 到 GPT

**提问**：词向量展开讲讲，之前只用过 word2vec，最好有可视化。

词向量和 word2vec 是同一个思路：一张可以训练的查找表，作用相似的字，向量也相似。图用 gpt.py 真实训练出来的字向量表画的（训练前一张、训练后一张）。

### 一句话

词向量（embedding）就是一张表：**每个 token 占一行，一行是一串数字**。查到哪行，就拿哪行来代表这个字。表里的数一开始是随机的，靠训练慢慢调。（见图1）

### 和 word2vec 比

| | word2vec | GPT 里的 embedding |
|---|---|---|
| 本质 | 一张查找表 | 一张查找表（`nn.Embedding`） |
| 怎么学的 | 单独训练：用一个词去猜它周围的词 | 和整个模型一起训练，目标是猜下一个 token |
| 单位 | 整词 | 字符（gpt.py）或子词（真实模型） |
| 规模 | 常见 300 维 | gpt.py：65 行 × 64 维；Llama 3 8B：128,256 行 × 4096 维 |
| 一词多义 | “bank”永远只有一个向量 | 查表只是起点，经过注意力层后，同一个词在不同句子里会变成不同的向量 |

最后一行最重要：word2vec 给的是“字典里的意思”，GPT 还会把它加工成“在这句话里的意思”。

### 怎么读图2

每个字有 64 个数，没法直接画。PCA 把它压成“最能拉开差距的 2 个方向”。两个字靠得近，就是它们的向量相似。␣ 是空格，带箭头的方框是换行。

- **① 训练前**：随机撒点，没有任何规律。
- **② 训练后的输入表**：还是很乱。这不代表没学到东西：PyTorch 默认的初始化太大，每个向量初始长度约 8，3000 步只挪了约 1.6，学到的规律被初始噪声盖住了。真实的 GPT 会用很小的初始值（GPT-2 是 0.02），另外这个模型也小。
- **③ 训练后的输出表 `lm_head`**：它是 64 × 65 的表，**每个字也对应一个 64 维向量**，意思是“模型想输出这个字时，内部状态该长什么样”。这里规律非常清楚：
    - 小写字母在左半边，大写字母在右半边
    - 元音 a、e、i、o 挤在左上角，大写元音 A、E、O、I 也靠在一起
    - 标点 . ; ? ! 抱成一团

最值得看的是第③格：没人告诉过模型什么是元音，它自己把 a、e、i、o 归到了一块。

用“余弦相似度”（两个向量方向有多接近，1 是完全同向）找最近的邻居：

| 字 | 最像它的字 |
|---|---|
| a | o 0.55，i 0.54，e 0.54 |
| . | ; 0.91，? 0.84，! 0.70 |
| A | I、B、E、O |
| t | c、s、n |

**为什么会自己聚类**：句号、分号、问号都出现在“一句话快结束”的地方，模型想预测它们时内部状态差不多，所以它们的向量被推到一起。这和 word2vec 里 king/queen 靠得近是同一个道理：**出现在相似位置的东西，向量会变得相似**。

**顺带一提**：GPT-2 干脆让输入表和输出表共用同一张表（叫 weight tying），可以省参数，也让输入端享受到输出端学得好的向量。

### 自己试试

训练完后，在 gpt.py 末尾加上这几行，查任意一个字的邻居：

```python
W = model.lm_head.weight.detach()
W = F.normalize(W - W.mean(0), dim=1)      # 去中心、缩成长度 1
sim = W @ W.T                              # 两两余弦相似度 (65, 65)
for q in ['a', '.', 'T']:
    v, ix = sim[stoi[q]].topk(5)
    print(q, [itos[int(j)] for j in ix[1:]])
```

把 `lm_head` 换成 `tok_emb`，就能看到输入表的邻居有多乱。

## 4. 输出表的含义 & token 能不能合到短句

**提问**：输出表是不是“每个输入词占一行、每列是下一个词的概率”？为了提高准确率，是不是还可以把短语、短句甚至固定长句也作为单位？

**第一点不太对。** “行是当前字、列是下一个字”其实是 **bigram 模型**那张 65×65 的表。GPT 的输出表是 **64×65**，它的输入不是“当前字”，而是经过注意力、已经融合了前文的 64 维状态。算出来的 65 个数只是**分数**，过了 softmax 才是概率。

**第二点只对一半。** 真实模型确实会把常见片段合成一个 token（**BPE**），但只合到词和词根，不合到短句：

- 词表一大，每个词条就很少出现，学不好；
- 也没法拼出没见过的组合；
- 合并的主要好处是让序列变短，而理解长句是注意力的活。

BPE 在阶段 3 会详细讲。

## 5. 注意力如何一路融合到输出

**提问**：对于输入的内容，怎么理解注意力、以及融合到输出表维度这个过程？

可以这样理解：每个字走的都是一条 64 维的“传送带”，注意力就是让它从前面那些字的传送带上拿东西。经过 4 层以后，最后一个字的向量已经装进了整句话，这时才用 lm_head 把它翻译成 65 个分数。（图3、图4 是模型读 “To be, or not to b” 时实际算出来的。）

### 整条流水线（图3）

关键只有一句：**从头到尾，每个位置始终是一个 64 维向量，只在最后一步才变成 65 个分数。**

| 阶段 | 形状 | 最后一格“b”里装着什么 |
|---|---|---|
| 查表 + 位置 | (25, 64) | 只有“我是 b，在第 25 位” |
| 经过第 1–4 块 | (25, 64) | 一层层混进前文：前面是空格、前一个词是 to、上半句是 to be…… |
| 取最后一格 | (64,) | “读完整句以后的理解” |
| lm_head | (65,) | 65 个分数，e 最高，是 9.21 |
| softmax | (65,) | e 68.8%，o 9.1%，r 5.1% …… |

所以“融合”不是在输出表那一步做的。所有融合都发生在中间的 4 个块里，输出表只是最后的“翻译”。

### 注意力在一个位置上具体做了什么

以最后的“b”为例，在某一层的某一个头里：

1. b 用自己的向量算出 **Q**：“我想找什么”
2. 前面 25 个位置（包括自己）各自算出 **K**：“我这里有什么”
3. Q 和每个 K 做点积 → 25 个分数 → softmax → 25 个权重（加起来等于 1）
4. 用这些权重把 25 个位置的 **V** 加权平均 → 得到一份“从前文收集来的信息”
5. **加回** b 自己的向量上（残差 `x = x + ...`），所以 b 原来的信息不丢，只是多了一些前文

就是第 4 步的“加权平均”和第 5 步的“加回去”，把前文融进了当前位置。

### 真实的注意力权重（图4）

每一行是一个字“在看谁”，颜色越深权重越大，每行加起来等于 1。右上角是空白的，这就是因果掩码：只能看前面。红框是最后一个“b”。

- **左图（第 2 层第 3 个头）**：几乎每个字都把权重全压在**前一个字**上。b 对它前面那个空格的权重是 0.97。这个头的工作就是把“我前面是谁”带过来，于是 b 知道自己是一个词的开头。
- **右图（第 3 层第 1 个头）**：更分散，把最近几个字混在一起看。b 的权重分成自己 0.64、t 0.13、n 0.11。

这些分工没人设计过，全是训练自己学出来的。下层的头从前一个字拿信息，上层的头就能在这个基础上看更长的模式，比如“空格 + b”后面常接 e。

### 一个容易忽略的点

训练时，这 25 个位置每一个都会过 lm_head，各自预测自己的下一个字（R 猜 O，RO 猜 M……），一句话就能出 25 道练习题，这正是因果掩码让它们不能偷看答案的原因。生成时只用最后一格。
